# Gym Scores — исправленная базовая версия

## Возможности
- Сервер Node.js + Express + Socket.IO.
- Судейский интерфейс и панель секретаря.
- Синхронизация текущей участницы с сервера.
- Судья может временно выбрать другую участницу; предупреждение показывает, что выбор отличается от выбора секретаря.
- Оценки сохраняются в PostgreSQL и загружаются после перезапуска.
- Проверка роли, участницы и формата оценки.
- Подтверждение успешной/неуспешной записи.

## 1. Требования
- Node.js 20 или новее
- PostgreSQL 14 или новее
- Файл `public/gymnasts.json` с массивом объектов и полями, как в исходном проекте.

## 2. Подготовить PostgreSQL
Создайте базу и пользователя, например, через psql под администратором PostgreSQL:

```sql
CREATE USER gym_scores_user WITH PASSWORD 'замените_на_сложный_пароль';
CREATE DATABASE gym_scores OWNER gym_scores_user;
```

Схема таблицы `scores` создаётся сервером автоматически при запуске.

## 3. Установка
Распакуйте проект. Скопируйте ваш настоящий `gymnasts.json` в папку `public`.
В корне проекта выполните:

```bash
npm install
```

Скопируйте `.env.example` в `.env` и заполните `DATABASE_URL`:
`postgresql://gym_scores_user:ВАШ_ПАРОЛЬ@localhost:5432/gym_scores`

Для локального PostgreSQL обычно оставьте `PGSSL=false`. Если провайдер облачной БД требует TLS, укажите `PGSSL=true`.

Запуск:
```bash
npm start
```

Откройте:
- `http://localhost:3000/secretary.html`
- `http://localhost:3000/judge.html`
- проверка сервера: `http://localhost:3000/health`

## 4. Подключение через интернет
`localhost` работает только на самом компьютере. Для доступа из разных сетей нужно развернуть Node-приложение на хостинге с HTTPS и доступной PostgreSQL (например, VPS или платформе приложения). Настройте переменные `DATABASE_URL` и `PGSSL` в панели хостинга, затем раздавайте участникам HTTPS-адрес приложения.

Не открывайте порт PostgreSQL всему интернету. Разрешите доступ к БД только с сервера приложения. Используйте HTTPS, сложные пароли и ограничение доступа.

## 5. Проверка
1. Откройте панель секретаря в одном окне и судейскую страницу в другом.
2. Нажмите «Следующая участница» у секретаря — судейская страница должна синхронно переключиться.
3. У судьи выберите другую участницу кнопками «Назад/Вперёд» — появится предупреждение; серверная участница секретаря не изменится.
4. Выберите роль DA1, введите `8.5` и отправьте. Панель секретаря должна показать 8.5 у нужной участницы и роли.
5. Перезапустите сервер. Сохранённая оценка должна остаться.
6. Повторная оценка для той же пары участница/роль обновляет предыдущую запись.

## Важные ограничения первой версии
- Диапазон оценки пока условно задан от 0 до 100. Перед соревнованиями замените его на разрешённые правилами конкретной дисциплины.
- Сейчас роль выбирается в браузере и не привязана к учётной записи. Это не достаточная защита для официальных соревнований. Следующий этап — вход секретаря/судей, серверное закрепление роли и аудит всех исправлений.
- Текущая участница хранится в памяти сервера и после перезапуска сбрасывается на первую. Оценки в PostgreSQL сохраняются. Следующим улучшением стоит сохранить состояние соревнования и добавить управление соревнованиями/потоками.
- Код рассчитан на один процесс приложения. При масштабировании на несколько экземпляров потребуется Socket.IO adapter (например, Redis) и общее состояние.
